Layering, Switching & Performance

Principles of Layering

Layering decomposes network functions into hierarchical layers, where each layer: (1) offers services to the layer above, (2) uses the services of the layer below, (3) communicates only with its peer on the other host using a protocol.

Key layering facts
  • Service = what a layer provides upward; protocol = how peers agree (horizontal). Service access point (SAP) = where a layer communicates with the one above.
  • PDU = Protocol Data Unit (segment, packet, frame…). SDU = Service Data Unit (payload carried inside a PDU). Encapsulation adds a header at each layer with PDU_above as payload.
  • OSI 7 layers: Physical → Data link → Network → Transport → Session → Presentation → Application.
  • TCP/IP 4 layers: Network Interface → Internet (IP) → Transport (TCP/UDP) → Application. IP + TCP/UDP + Application is what GATE actually tests.

GATE trap
Routing happens at the network layer; address resolution (ARP) and reliable delivery / flow/congestion control happen at transport. A per-hop switch carries the frame inside out but the end-to-end transport PDU is untouched by intermediate routers — routers modify the IP header (TTL) but never re-order or re-transmit TCP segments.

Circuit / Packet / Virtual-Circuit Switching & Performance Metrics

Types of switching

TypeConnection setupResource reservationKey property
Circuit switchingdedicated path firstYes — bandwidth reserved for the callfixed delay, guaranteed bandwidth, wasteful when idle (telephony, TDM)
Packet switching (datagram)noneNo — store-and-forwardbest-effort, each packet routed independently (IP)

Performance metrics (used to compute transfer time)
Transmission time: Tt = L / B (size of the message ÷ link bandwidth).
Propagation delay: Tp = d / v (distance ÷ propagation speed).
End-to-end delay ≈ Tt + Tp + queuing + processing.
Round-trip time (RTT) ≈ 2·Tp + 2·Tt (propagation-dominated).
Characteristic ratio: a = Tp / Tt. Bandwidth–delay product = B · Tp = "bits in flight".
Efficiency of stop-and-wait: η = Tt / (Tt + 2Tp) = 1 / (1 + 2a).

Always check units: convert bytes to bits (×8) and km to metres before dividing by bandwidth in bps and speed in m/s.

Worked example — stop-and-wait efficiency and RTT-delimited transfer

Link: B = 1 Mbps, one-way distance 1000 km, propagation speed 2×10⁸ m/s, frame 1000 bytes (8000 bits).

Tt = 8000 / 10⁶ = 8 ms.   Tp = (1000×10³)/(2×10⁸) = 5 ms.

a = Tp/Tt = 5/8 = 0.625   ⟹   η = 1/(1+2×0.625) = 1/2.25 ≈ 0.444 (44.4%).

Sanity check with the raw form: η = 8/(8 + 2×5) = 8/18 ≈ 0.444 ✓ (acknowledgements obey the same 2Tp wait).

Worked example — satellite link shows why sliding window is needed

Geostationary satellite: Tp = 270 ms, frame 1000 bytes at B = 1 Mbps   ⟹   Tt = 8 ms, a = 270/8 = 33.75, 1+2a = 68.5.

Stop-and-wait: η = 1/68.5 ≈ 0.0146 (1.5%) — the link is nearly idle waiting for ACKs.

With a window of N = 20 frames: η = N/(1+2a) = 20/68.5 ≈ 0.292 (29%) — a 20× improvement (until N reaches 1+2a, beyond which η caps at 1).

GATE trap
Students forget two propagation delays for stop-and-wait: the ACK must travel back. Always use Tt/(Tt+2Tp). Similarly, minimum TCP frame/PDU computations use RTT ≈ 2Tp, not Tp. And conversion 1 byte = 8 bits is the single most common arithmetic error in the subject.

Data Link — Error Detection

Parity, Checksum, CRC & Hamming Distance

The data link layer detects (and sometimes corrects) bit errors introduced by the channel. GATE tests the detection capability given a minimum Hamming distance, and the CRC computation.

Hamming distance — the one rule you need
A code with minimum Hamming distance dmin:
  • Detects up to dmin − 1 bit errors.
  • Corrects up to ⌊(dmin − 1)/2⌋ bit errors.
To correct t errors you need dmin ≥ 2t+1 (Hamming bound); to detect s errors you need dmin ≥ s+1.
SchemeHow it worksLimitation
Even/odd parityadd 1 bit so the count of 1s is even/odddetects odd number of errors only; even number slips through
Two-dimensional parityparity per row and columndetects & corrects single-bit errors
Checksumsum of words, one's-complement sum, carry wrappedlightweight; can miss symmetric errors (used by TCP/IP)
CRCpolynomial long division mod-2 by generator G(x)detects all single-bit, double-bit, and all odd errors; burst errors up to polynomial degree
CRC — how to compute the appended remainder
1. Append r zero bits, where r = degree of the generator polynomial G(x).
2. Divide (mod-2, i.e. XOR) message+zeros by G; the remainder is the CRC (r bits).
3. Transmit: M + CRC. Receiver divides by G again — a zero remainder ⟹ no (detectable) error.
Selecting G with degree r guarantees detection of all bursts of length ≤ r.
Worked example — CRC-3 division, M = 11010011101100, G = 1011

G = 1011 is x³ + x + 1, so r = 3. Append three zeros: dividend = 11010011101100000.

Perform mod-2 (XOR) division by 1011. The division leaves remainder 100.

Transmitted codeword = 11010011101100100. A 3-bit generator catches every burst error of length ≤ 3 and every odd number of errors.

Check principle: on the receiver side, dividing the received word by 1011 gives remainder 0 iff no detected error.

Worked example — capability from Hamming distance

A code has dmin = 4.

Detection: up to dmin − 1 = 3 errors. Correction: up to ⌊(4−1)/2⌋ = 1 error.

Because a 3-error detection and 1-error correction are not simultaneously guaranteed, GATE phrases it as separate capabilities.

GATE trap
With single parity, an even number of bit flips (2, 4, …) is undetected. With CRC, the remainder is computed on message + r zeros, not on the message alone, and r equals the degree of the generator, not its number of bits — for "1011" r = 3, so 3 zeros appended, not 4.

Data Link — MAC & Ethernet

MAC Protocols & CSMA/CD

Medium Access Control decides who may transmit on a shared channel. Static (TDMA/FDMA) and random-access (ALOHA, CSMA, CSMA/CD) families are tested — CSMA/CD is the classic GATE focus.

ProtocolCollision handlingNote
Pure ALOHAsend anytime; collided frames retransmitted randomlymax throughput = 1/2e ≈ 0.18
Slotted ALOHAtransmit only at slot boundariesmax throughput = 1/e ≈ 0.37
CSMA (persistent/nonpersistent)sense carrier before sending; still collide if two start togetherreduces but does not remove collisions
CSMA/CDabort on collision while transmitting, jam, backoffused by Ethernet; needs min frame time ≥ 2·Tp
Token ring / token bustoken gives sole right to sendcollision-free, deterministic
CSMA/CD — minimum frame size (the one formula)
For a sender to detect a collision it must still be transmitting when the echo returns: Tt ≥ 2·Tp.
Since Tt = L/B: Lmin = 2·Tp·B = 2·(d/v)·B bits.
The slot time = 2·Tp. After a collision each station backs off a random number of slot times.
Worked example — CSMA/CD minimum frame over 2 km

B = 10 Mbps, cable length 2 km (2000 m), propagation speed v = 2×10⁸ m/s.

Tp = 2000/(2×10⁸) = 10 µs  ⟹  2·Tp = 20 µs.

Lmin = 2·Tp·B = 20×10⁻⁶ × 10⁷ = 200 bits.

If frames were shorter than 200 bits, a sender could finish before the echo of a collision arrives and never detect it.

GATE trap
The minimum frame formula uses the round-trip (2·Tp), and Tp = d/v with distance in metres and speed in m/s. The result is in bits — divide by 8 if asked for bytes. When the exam gives the answer in bytes (Ethernet standard 64 bytes = 512 bits), that reflects a 10 Mbps, 2.5 km cable where 2·Tp·B = 512 bits.

Ethernet Frames & Addressing

Ethernet is the canonical CSMA/CD LAN. Frames are addressed by 48-bit MAC addresses (also called physical/hardware addresses, flat and unique per NIC).

Frame partPurpose
Preamble + SFDsynchronise receiver before data
Destination / Source MAC48-bit addresses of the frame endpoints on the LAN
Length / Typedistinguishes Ethernet II (type) vs IEEE 802.3 (length)
Payloadupper-layer PDU (the IP packet), min 46 bytes
FCS (CRC-32)32-bit CRC over the frame fields
  • MAC addressing domains: MAC for same-switch delivery; IP for end-to-end across routers. A router strips the incoming frame and re-frames into a new frame per hop, so destination MAC changes at each hop while the IP destination never changes.
  • Broadcast (all ones) ff:ff:ff:ff:ff:ff, multicast (LSB of first byte set), unicast.
  • Address resolution: to send to an IP address on the same network, the host broadcasts an ARP request "who has IP x?"; the owner replies with its MAC, cached in an ARP table.
  • Full-duplex switched Ethernet has no carrier sensing and no collisions — CSMA/CD is disabled, which is why modern switches remove the minimum-frame constraint.
Quick memory
"MAC = hop-by-hop inside a LAN; IP = end-to-end across the Internet — MAC changes hop to hop, IP does not." That one sentence answers many 1-mark questions.
GATE trap
A switch forwards frames and learns MAC addresses (layer-2 device); a router forwards packets using IP addresses (layer-3). Do not confuse ARP (broadcast, resolved within a single IP network) with IP routing across networks — ARP never crosses a router boundary.

Routing Algorithms

Distance Vector (Bellman–Ford)

Distance vector (DV): every router periodically sends its entire routing table (distance to every destination) only to its direct neighbours. Each router updates via the Bellman–Ford recurrence:

Bellman–Ford recurrence
dX(Y) = min over neighbours N of ( cost(X, N) + dN(Y) ).
The classic example: RIP uses hop count; Bellman–Ford guarantees convergence in ≤ V−1 iterations.
  • Count-to-infinity problem: when a link goes down, DV can slowly propagate the wrong distance (incrementing by 1 each round) — the split horizon (don't advertise routes back to the neighbour you learned them from) and poison reverse mitigate it.
  • Slow convergence, small table sharing — used in small networks.
Worked example — one distance-vector update round

Two neighbours for router X: X–A = 5, X–B = 20. A advertises A–C = 20; B advertises B–C = 10.

Candidates for X→C: via A = 5 + 20 = 25; via B = 20 + 10 = 30.

Also X advertises X–C = 20 directly (say). New best for X→C = min(20, 25, 30) = 20 — unchanged here, but had the direct path cost 30, the min would be 25 → X would route C via A.

GATE trap
DV routers exchange tables only with one-hop neighbours; link-state (next) floods topology to every router in the network. If the question says "exchange with immediate neighbours", it is DV. Count-to-infinity is a distance-vector-only weakness.

Link State (Dijkstra) & Comparison

Link state — Floyd/Dijkstra approach
1. Each router floods the network with its own link costs (link-state advertisement, LSA).
2. Every router now holds the complete topology and independently runs Dijkstra to build its own SPF tree.
3. Fast, consistent convergence; the algorithm is O(V²) (or O(E log V)) per source. OSPF is the canonical protocol.
Worked example — Dijkstra from A (links: A–B 1, A–C 4, B–C 2, C–E 3, B–D 6, C–D 5, D–E 2)

Init: dist(A)=0; others ∞.

1. Settle A; relax B=1, C=4.

2. Nearest B=1; relax C=1+2=3 (was 4 ✓ update), D=1+6=7.

3. Nearest C=3; relax D=3+5=8 (no, 7 better), E=3+3=6.

4. Nearest E=6; relax D=6+2=8 (no).

5. Nearest D=7.

Result: A–B=1, A–C=3, A–D=7, A–E=6. Shortest A→D = 7 via A–B–D (1+6), not the A–C–D path (3+5=8).

GATE trap
Dijkstra settles the closest unvisited node next and never revisits a settled node — relaxing through an already-settled node can never lower its distance on a positive-cost graph. If the question's edge weights can be negative, Dijkstra fails and you must reason with Bellman–Ford instead.

IP Addressing, CIDR, NAT & Support Protocols

IPv4 & Classless CIDR Addressing

  • IPv4 is a 32-bit address, 8 bits per octet. Classful ranges (historical, still asked): A 1–126, B 128–191, C 192–223, D 224–239 (multicast), E 240–255 (reserved).
  • CIDR (Classless Inter-Domain Routing) separates the address from the class: write a.b.c.d/n where n = number of network bits (the prefix). The block has 232−n addresses; first = network, last = broadcast, the rest are usable hosts.
The five CIDR facts that do 80% of numerical work
1. Block size = 232−n addresses.
2. Usable hosts per block = 232−n − 2 (subtract network + broadcast).
3. Network address = "address AND mask"; broadcast = network + block − 1.
4. Subnet mask octets: /24=255.255.255.0, /25=.128, /26=.192, /27=.224, /28=.240, /29=.248, /30=.252, /31=.254.
5. Last usable address = broadcast − 1 = network + block − 2.
Worked example — a single IPv4 host in a /26

Host 192.168.10.5/26.

Block = 232−26 = 2⁶ = 64 addresses. The /26 networks of 192.168.10.x are 0–63, 64–127, …

Address .5 falls in the first block: network = 192.168.10.0, broadcast = 192.168.10.63, usable hosts 192.168.10.1 – .62 (62 hosts).

Subnet mask /26 = 255.255.255.192.

Worked example — how many usable addresses does a /22 give?

Block = 232−22 = 2¹⁰ = 1024 addresses.

Usable = 1024 − 2 = 1022 hosts.

Mask /22 = 255.255.252.0. If an organisation needs exactly 510 usable hosts, the smallest block that fits is /23 (512 addresses, 510 usable).

GATE trap
The biggest CIDR trap is subtracting 2 only once (network + broadcast) — right — versus subtracting 2 per subnet in a VLSM question. Also: usable = block − 2, never block − 1. And if a question says "usable addresses ≥ 500", convert to the block that leaves ≥ 500 after subtracting 2 (choose /23 over /24, since /24 gives only 254).

Subnetting & VLSM

Subnetting carves one block into several smaller blocks. Each subnet loses its own network and broadcast address, so total usable = Σ(2block_host_bits − 2) per subnet.

Subnetting math
If you further divide a /p block into 2k subnets, each subnet is /(p+k) with 232−(p+k) addresses. The mask adds k bits: block size for each subnet = 232−(p+k), usable per subnet = that minus 2.
Worked example — divide a /24 into four /26 subnets

Take 200.1.2.0/24. Four equal subnets ⟹ k = 2 (2² = 4), each becomes /26 with 2⁶ = 64 addresses and 62 usable.

Subnet 1: 200.1.2.0 – .63 (network .0, broadcast .63).
Subnet 2: 200.1.2.64 – .127 (network .64, broadcast .127).
Subnet 3: 200.1.2.128 – .191.
Subnet 4: 200.1.2.192 – .255.

Total usable = 4 × 62 = 248 (not 254 — the original single /24 had 254 usable). Every split costs 2 addresses per subnet in usable hosts.

Worked example — VLSM with mixed sizes

From 192.168.0.0/24 you need one /26 (64 addrs), one /27 (32 addrs), and one /28 (16 addrs).

Allocate largest first: 192.168.0.0/26 (0–63), then 192.168.0.64/27 (64–95), then 192.168.0.96/28 (96–111).

The wasted remainder (112–255) is not a valid reuse for those sizes unless recomputed — this is why careful bit layout beats guesswork.

GATE trap
A /30 block has exactly 2 usable addresses (typical point-to-point link); a /31 has 0 usable by the "−2" rule (though RFC 3021 exempts point-to-point). Questions love "how many subnets can /24 be split into of /27?" — answer 23 = 8

Private IPv4 ranges (RFC 1918) — memorise

These never route on the public Internet; NAT translates them at the boundary.
  • NAT with port map (NAPT/pat): the NAT router keeps a table (private IP:port) ↔ (public IP:port), rewriting source IP/port outbound and destination IP/port inbound, so thousands of internal hosts can share one public address.
  • DHCP DORA: Discover (broadcast), Offer, Request, Ack. Leases carry a TTL; hosts re-request before expiry.
  • ARP caching & gratuitous ARP: replies are cached; a host announces its new MAC by gratuitous ARP.
  • ICMP is not TCP/UDP: it has its own header and is carried inside IP precisely because it exists to report IP-level problems.
Ping = ICMP, not TCP
"What protocol does ping use?" is a guaranteed-style 1-mark question. Ping uses ICMP echo (request/reply), on top of IP — no TCP port. Traceroute exploits the TTL for each hop, again via ICMP.
GATE trap
NAT breaks the end-to-end argument: a NAT router is stateful and cannot simply forward inbound connections without a configured mapping — this is why incoming client–server connections to a private host need port forwarding. Do not claim "DHCP" when the exam means dynamic address allocation done at boot across a LAN versus NAT doing translation of already-assigned addresses.

Flow Control & Sliding Window

Why flow control exists

Flow control prevents a slow receiver from being flooded by a fast sender. TCP uses a sliding window of size min(cwnd, rwnd) where rwnd is the receiver's advertised window and cwnd is the sender's congestion window.

Sliding-window efficiency (reuse from Section 2)
With the characteristic ratio a = Tp/Tt and window size N frames:
η = N / (1 + 2a)  (capped at 1 when N ≥ 1+2a, i.e. the pipe is full).
Throughput = η × B. So the window ≥ 1 + 2a keeps the link 100% busy.
  • Stop-and-wait = sliding window with N = 1: send one frame, wait for ACK.
  • Go-Back-N: sender window ≤ 2n − 1 (n sequence-number bits); on error, retransmits from the lost frame onward (cumulative ACK).
  • Selective Repeat: only the missing frame is retransmitted; requires window ≤ 2n−1 (half the sequence space) to disambiguate new from retransmitted frames; per-frame ACKs.
Worked example — sliding window on a 33.75-a satellite link

a = 33.75, so 1 + 2a = 68.5 frames keep the pipe full.

With N = 30: η = 30/68.5 ≈ 0.438 (43.8%). With N = 70 ≥ 68.5: η caps at 1.0.

A stop-and-wait link on the same line would sit at η = 1/68.5 ≈ 1.5% — windowing buys a 30×+ gain.

GATE trap
Sequence-number window limits: Go-Back-N needs 2n − 1 ≤ window, but Selective Repeat needs 2n−1 (only half the sequence space). With 3 seq bits: GBN max window 7, SR max window 4. Mix these up and a numeric question is lost.

Congestion Control & TCP Congestion-Window Traces

Congestion control throttles the sender when network buffers (not the receiver) are saturated. TCP uses the congestion window (cwnd) with two phases:

TCP congestion-control recipe
  • Slow start (SS): cwnd doubles every RTT (1 → 2 → 4 → 8 → …) until it hits ssthresh.
  • Congestion avoidance (CA): cwnd grows by 1 segment per RTT (additive increase) after ssthresh, until loss.
  • Triple duplicate ACK: fast retransmit; set ssthresh = cwnd/2, cwnd = ssthresh, grow additively (fast recovery).
  • Timeout: ssthresh = cwnd/2, cwnd resets to 1 MSS and restarts slow start.
TCP window = min(cwnd, rwnd). This is the AIMD behaviour — Additive Increase, Multiplicative Decrease.
Worked example — a complete congestion-window trace

Start: cwnd = 1, ssthresh = 16.

Slow start (RTTs 1–6): 1 → 2 → 4 → 8 → 16. At cwnd = 16 = ssthresh, slow start ends.

Congestion avoidance (RTTs 7–9): add 1 per RTT: 17 → 18 → 19.

Loss at cwnd = 19 (triple duplicate ACK): ssthresh = 19/2 ≈ 9, cwnd = 9, then additive: 10, 11, …

Had it been a timeout at cwnd = 19 instead: ssthresh = 9 but cwnd = 1, restarting slow start 1 → 2 → 4 → 8, then additive from 9.

Pattern to recognise: SS = doubling, CA = +1/RTT, drop = halve (ssthresh) + reset cwnd to 1 (timeout) or to ssthresh (3 dup-ACK).

GATE trap
On 3 duplicate ACKs, cwnd drops to the new ssthresh (fast recovery, no pipe drain). On a timeout, cwnd resets to 1 (slow start restart). Mixing these two is the highest-frequency error in congestion-trace questions — a double-ACK (not triple) does not trigger fast retransmit.

Sockets, Ports & Handshake

A socket = (IP address, port) names one transport endpoint. A connection between two endpoints uses the 4-tuple; the receiving end can multiplex many connections onto one (IP, port) via the (client IP, client port) pair.

  • Well-known ports 0–1023 for standard services; ephemeral 1024–65535 chosen by clients.
  • TCP connection setup: SYN (client, seq = ISN) → SYN+ACK (server) → ACK (client). Teardown uses FIN/ACK in each direction (TIME_WAIT on the closer).
  • UDP socket needs no connection: a datagram is sent and forgotten; a single UDP socket can talk to many peers on the same (IP, port) pair.
Handshake fact
Number of handshakes to set up and tear down a TCP connection = 3 + 4 = 7 messages (3 for SYN setup, 4 for FIN teardown — one FIN + ACK per direction), or 3 messages for setup alone.
GATE trap
Port numbers identify processes/services at transport, not hosts. Two different TCP connections to the same server port are distinguished by the client port (and client IP) — a server's (IP, 80) alone is shared by thousands of concurrent HTTP clients.

Application Layer — DNS, SMTP, HTTP, FTP

DNS — Naming & Resolution

DNS translates human-readable domain names to IP addresses. It is a distributed, hierarchical database with root servers → TLD servers → authoritative servers.

Normal DNS queries use UDP port 53. TCP 53 is used only for large replies (zone transfers) or when a response exceeds a UDP datagram — a standing GATE favourite.

DNS is not one central server — it is hierarchical and distributed. MX records point to mail servers, not web servers; CNAME is an alias to another name. Never answer "a single flat table" for how DNS finds an address.

SMTP & FTP

SMTP (Simple Mail Transfer Protocol) delivers mail from client to server and server to server, over TCP port 25. Retrieval of mail from a mailbox uses POP3 (110) or IMAP (143). Email on the wire is 7-bit ASCII (MIME adds encoding for binaries/attachments).

FTP (File Transfer Protocol, ports 21 control + 20 data) uses two parallel connections: one for commands (control) and one for the actual file transfer (data). It is stateful (login stays open).

ProtocolPortTransportRole
SMTP25TCPsending mail
POP3 / IMAP110 / 143TCPretrieving mail
FTP21, 20TCPfile transfer (two channels)
GATE trap
SMTP sends mail; it does not read mail from your inbox. FTP uses two TCP connections (control + data); HTTP uses one. "SMTP server" answers: send direction only — retrieval is POP3/IMAP.

HTTP & Web

HTTP (HyperText Transfer Protocol) is a request–response application protocol over TCP port 80 (HTTPS 443 adds TLS). A client sends a request (method, URL, headers) and the server returns a response (status line, headers, body).

ElementNotes
MethodsGET, POST, PUT, DELETE, HEAD
Status codes2xx success, 3xx redirect, 4xx client error (404 not found), 5xx server error
Statelesseach request independent — cookies/sessions add state on top
Persistent vs non-persistentHTTP/1.1 keeps the connection open (persistent) to reuse it for many objects, cutting per-object handshake/TCP-setup overhead

Cookies are small tokens a server stores via the client to fake state (session tracking). Cache-Control and ETags let proxies/clients reuse responses. HTTPS = HTTP over TLS (443).

GATE trap
HTTP is stateless — the server forgets between requests; state is layered on with cookies/sessions, not built into HTTP. Non-persistent HTTP/1.0 opened a new TCP connection per object; HTTP/1.1's persistent connection is why a page with many images loads faster without re-handshaking for each one.

Exam Strategy for Computer Networks

Order of attack (8 marks ~ 12–15 min)
  1. Subnetting / CIDR NATs first (~3 min). Convert bytes→bits upfront, subtract 2 once, use block = 232−n. Highest accuracy in the subject.
  2. Efficiency / CSMA-CD numerics (~3 min). Recall a = Tp/Tt; η = 1/(1+2a) or N/(1+2a); min frame = 2·Tp·B. These are formula-plug-in questions.
  3. TCP congestion trace (~2 min). Distinguish timeout (cwnd→1) from triple-dup-ACK (cwnd→ssthresh).
  4. Concept MCQs (~4 min). Layer-vs-protocol, port numbers, DV vs LS, DNS/HTTP stateless — answer from the tables.
